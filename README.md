# belalhanafy.com

Personal site for Belal Hanafy, PhD — Senior Scientist, Pharmaceutical Sciences, AstraZeneca.

Next.js 16 (App Router) + TypeScript + Tailwind v4, built as a **fully static export**. No server, no database, no backend of any kind.

---

## Running it

Node 24 is installed at `~/.local/node` and is not on the global `PATH`. Either add it:

```bash
echo 'export PATH="$HOME/.local/node/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
```

or prefix each command with `PATH="$HOME/.local/node/bin:$PATH"`.

```bash
npm run dev      # http://localhost:3000
npm run build    # static export into ./out
npm start        # serve ./out on http://localhost:4321
```

## Checks

```bash
npm run lint               # eslint
npm run typecheck          # tsc --noEmit
npm run check:privacy      # asserts no phone number and no CV in the build output
npm run check:responsive   # horizontal-overflow check, all routes x 375/768/1440
```

`check:responsive` needs the site being served — run `npm run build && npm start` in another shell first. It drives headless Chrome over the DevTools protocol, because Chrome on macOS enforces a minimum window width and `--window-size=375` alone silently renders wider than asked.

## Regenerating assets

```bash
npm run assets    # image renditions + copies the PRELIVE tool into public/
```

Source files live in `~/Documents/Work/Projects (AI)/Personal website ` — **note the trailing space** in that folder name; always quote the path.

The OG card is rendered from `scripts/og-template.html` with headless Chrome. It is a manual step because it only needs redoing when the headline or cover changes:

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --hide-scrollbars --allow-file-access-from-files --window-size=1200,630 \
  --default-background-color=0f171cff --screenshot="$PWD/public/og.png" \
  "file://$PWD/scripts/og-template.html"
```

## Editing content

Everything routine is in `content/` and `lib/site.ts` — no component edits needed.

| Change | File |
|---|---|
| Add a publication | `content/publications.ts` |
| Reword a research theme | `content/research.ts` |
| Add a journal cover | `content/covers.ts` |
| Name, role, social links | `lib/site.ts` |

**Adding a paper:** append to the `publications` array. Verify the DOI against Crossref rather than transcribing it:

```bash
curl -s "https://api.crossref.org/works/10.xxxx/yyyy" | python3 -m json.tool | head -40
```

Set `openAccess` from the licence Crossref reports. If it is not an open licence, link the DOI only — do not host the PDF.

### Things that are deliberate

- **No CV is published**, in any form. The source CV contains a personal phone number; `npm run check:privacy` enforces that neither it nor the number reaches the build.
- **The email address is never a literal string in the HTML.** `components/Email.tsx` assembles it after hydration.
- **The PRELIVE file is byte-identical to the publisher's.** It is machine-generated by JMP; reformatting it will break it. It lives at `public/embeds/prelive.html`, *not* `public/tools/prelive/`, because the Next route of that name emits its own `index.html` there and the two would collide.
- **Dark theme only.** The cover art is dark-background-native and a light mode fights it.

## Deploying

### 1. GitHub

```bash
gh repo create belalhanafy-site --public --source=. --remote=origin --push
```

### 2. Vercel

Import the repo at [vercel.com/new](https://vercel.com/new). Framework preset **Next.js**; everything else default. The free Hobby tier is licensed for non-commercial use — if the site ever advertises consulting, it needs Pro.

### 3. Domain

Buy `belalhanafy.com` at **Cloudflare Registrar** (at-cost renewals, free WHOIS privacy). Add it in Vercel → Project → Settings → Domains, then in Cloudflare DNS:

| Type | Name | Value | Proxy |
|---|---|---|---|
| A | `@` | `76.76.21.21` | **DNS only** |
| CNAME | `www` | `cname.vercel-dns.com` | **DNS only** |

Both records must be **grey-cloud (DNS only)**. Cloudflare's orange-cloud proxy in front of Vercel causes redirect loops and blocks certificate issuance.

Then verify:

```bash
curl -sI https://belalhanafy.com | head -1
curl -sI https://www.belalhanafy.com | grep -i location
```

### 4. After going live

- Paste the URL into [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/) to prime the OG card.
- Submit `https://belalhanafy.com/sitemap.xml` in Google Search Console.
- Add the URL to the ORCID and LinkedIn profiles — that reciprocal link is what ties the site to the existing scholarly identity.

## Measured at build time

Lighthouse, desktop preset, against the static output. Measured before the
cover-art page was folded into Publications; worth re-running after that
change.

| Route | Perf | A11y | Best practices | SEO |
|---|---|---|---|---|
| `/` | 98 | 100 | 100 | 100 |
| `/research/` | 99 | 100 | 100 | 100 |
| `/publications/` | 99 | 100 | 100 | 100 |
| `/tools/` | 98 | 100 | 100 | 100 |
| `/about/` | 99 | 100 | 100 | 100 |
| `/tools/prelive/` | 80 | 100 | 78 | 100 |

`/tools/prelive/` scores lower because of the 1.6 MB third-party JMP payload. Its console messages — a 404 on `/api/webjmp` and a deprecated `unload` listener — come from that file. The 404 is JMP probing for a live JMP server; it falls back to the embedded model, which is why the profiler works. None of it is fixable without modifying a file that must stay byte-identical.
